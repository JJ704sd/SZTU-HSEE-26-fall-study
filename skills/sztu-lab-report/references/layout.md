# Word/PDF 版式与核对

## 先继承模板，再设新增样式

复制本次教师 DOCX 模板，在副本中填充。保留原校徽、评分表、字段分组、封面下划线、页眉页脚及正文表格容器；不要从截图重画已存在的封面。嵌入式、医院信息系统和 NLP 的本地模板均有封面评分表与带边框的正文表格。使用这些原模板时在容器内编写，不无意把正文移到框外。

编辑含多个 run 的字段时，保留原格式和域。避免对含图片、域或签名的整段直接赋 `paragraph.text`，这会清除 run 及嵌入对象。复制完整模板比拷贝 `document.xml` 单个片段可靠；后者还涉及样式、编号和图片关系。

不要把教师版的红色提示字、截图中的绿色背景、空白占位页照搬成最终设计。PPT 中的绿色来自示例截图，不是已核实的报告底色。提示文字在完成对应内容后移除；评分表、签名区等结构保留。

## 需要精确测量时

读取当前模板，先使用下文的摘要命令定位页面、常见字体和容器宽度；对某个字段有疑问时再展开明细。历史数值集中在 [模板测量快照](template-measurements.md)，仅供当前模板一致时参考。

## 缺少明确格式时的建议

仅在教师模板没有对应样式、用户也未指定时，对新写的普通正文采用以下起点。它是本 Skill 的建议，不写成教师要求；分页时先删重复内容和无关完整代码，不先缩字。

| 角色 | 建议 |
| --- | --- |
| 普通正文 | 宋体 `12 pt`，英文与数字 Times New Roman；两端对齐；首行缩进 2 字符；`1.5 倍`行距；段前后 `0 pt`。 |
| 一级节标题 | 黑体 `14 pt` 加粗，沿课程原编号；与下段同页。 |
| 子标题 | 宋体或黑体 `12 pt` 加粗；如 `2.1`，仅在内容需要时新增。 |
| 代码 | 英文 Consolas，中文宋体；`9–10 pt`、单倍至 `1.15 倍`行距、左对齐、无首行缩进；可用浅灰底纹。 |
| 图题、表内文字 | 宋体 `10.5 pt` 左右，根据内容调整；保持可读，不能统一缩成小字塞页数。 |

中文标点按正常中文书面习惯；技术标识符、文件名和代码保持原样。公式使用可编辑公式或清晰矢量内容，说明符号、单位及适用条件，不截图一大段公式后让字号不可读。

## 图、表与代码

- 图紧邻所说明的操作或结果，顺序编号；图题置图下，表题置表上。若模板已有约定则沿用。每张结果图在正文中解释观察到什么。
- 使用真实截图与原始数据绘图。示意图/流程图应标明其用途，不能仿造终端、编译器或开发板画面来充当实测。
- 流程图按实际判断、分支与循环绘制；导出到 Word/PDF 时使用可嵌入的清晰图形，不能把未渲染的 Mermaid 源码当图。
- 图片等比缩放，优先裁掉与任务无关的桌面区域。落版后检查图中文字；超宽时分图或调整内容，不能仅把整屏截图缩小。
- 表格标单位并统一有效位数；跨页表重复表头，避免表头落在页底而数据在次页；普通短行不拆跨页。嵌套表宽要扣除外层单元格边距。
- 只呈现说明本题修改的关键代码及必要上下文，有中文注释；保持缩进。长代码行先换成语义合适的多行或缩短展示范围，不能改错代码或把换行拼成一条无效语句。
- 封面与正文使用显式分页关系，优先保持封面一页；正文可按模板表格自然续页。标题、图题与相应内容尽量不分离，不靠大量空行控页。

## 签名和封面

封面逐字段核对本次课程编号、课程名、实验名称、班级、指导教师、报告人、学号、合作者、组号、地点、实验时间和提交时间。没有组号不猜；已知“不适用”可据本次实际处理，不能把空白、无、不适用互相默认替代。教师评分、签名和批改日期保持空白。

课程要求签名时，使用本人提供或确认的资源；打字姓名不自动等于本人手写签名。具体形式按本课要求，医院信息系统模板另有明确限制。缺少时保留签名位置，并在交付说明中列为待补，不把提示写成签名内容。

## 只读测量脚本

```powershell
python -X utf8 "<skill-dir>/scripts/inspect_docx.py" "<本次模板.docx>" --summary
python -X utf8 "<skill-dir>/scripts/inspect_docx.py" "<本次模板.docx>" --include-text --output "<新的检查结果.json>"
```

脚本仅依赖 Python 标准库。先用 `--summary` 查看页面、常见格式、相关样式、表格和图片尺寸；需要定位到段落时使用默认明细模式。`--include-text` 可在明细中保留同一段内的换行和制表符；文本框的独立段落单列，避免在宿主段重复。默认不输出正文，带文本的本地检查文件不用于对外发送。`--summary` 与 `--include-text` 二选一；`--output` 拒绝覆盖已有文件。

输出中的段落与 run 属性是**原始显式值**，不是已完整计算的有效格式。需要结合输出中的默认属性、样式继承、字符样式和主题字体判断；表格条件格式等仍需原文件检查。`styles` 不存在某个值不等于 Word 实际没有该值。

维护检查脚本时，可运行 `python -X utf8 "<skill-dir>/scripts/tests/test_inspect_docx.py"`；测试使用独立临时 DOCX，不依赖本地课程文件，也不代替报告视觉检查。

## 文件验证

1. 先检查 DOCX 可打开、样式和结构保留，数据/代码没有截断；对照课程要求检查文件名及必备项。
2. 如可用 `documents` 技能，按其渲染路径生成页面图；`pdf` 技能用于最终 PDF 检查。当前环境可用工具优先，不把机器特定路径写死。LibreOffice 只使用工具定位到的 bundled 版本；没有时可用当前可用的 Word 导出或项目已验证后端。没有实际渲染结果时明确说明，不能把 XML 检查称为视觉验收。
3. 对最终导出的每页查看封面是否完整、正文是否出框、代码/图片是否可读、中文是否缺字、标题表头是否孤立、是否有意外空页。NLP 另检查课程页数上限。
4. PDF 应由最终 DOCX 导出。若既有项目必须用两套独立排版后端，分别比较段落、表格、图、代码与页数，不能只凭文件名一致认为内容一致。
5. 本次编辑、导出和检查的范围在交付中说清；未进行教学平台导入或教师验收时不作相关成功声明。
